# 10/26 폴 실행 기록·Flow 게시 초안

상태: **10/26 USB·STA·카메라 초기화 확인, 사진·웹·음성은 다음 단계**. 10/22 사진 수신 기록을 오늘의 성공으로 쓰지 않는다.

## 폴이 직접 처음부터 실행

1. Mac과 ESP32 전원/USB를 연결한다. 시리얼 모니터가 이미 포트를 쓰면 그 터미널에서 Control+C로 종료한다.
2. Mac에서 `arduino-cli board list`로 USB 포트를 확인한다. 포트가 보이는 것과 Wi-Fi/사진이 되는 것은 각각 따로 확인한다.
3. 프로젝트 루트에서 `arduino-cli monitor -p /dev/cu.usbmodem1101 -c baudrate=115200,dtr=on,rts=off`를 실행한다. 버전, networkMode, ip, cameraOk, cameraProfile을 적는다. 로그가 잘리면 모니터에 `status` 후 Enter.
4. 모니터를 Control+C로 닫고, 별도 터미널에서 `python3 scripts/probe_clip_snapshot.py http://<방금 확인한 IP> --profile stable`을 실행한다. HTTP 200, 수신 길이 일치, JPEG 표식 True를 확인한다. 토큰은 로컬 secrets.h에서 읽으며 화면에 공개하지 않는다.
5. `cd web` 후 `CLIPSENSE_HTTP_LOCAL=1 npm run dev -- --port 5174 --strictPort`를 실행한다. 5174가 이미 사용 중이면 기존 서버 터미널에서 Control+C로 종료하고 다시 실행한다. 웹은 React/Vite이며, Python은 기기 사진 진단 도구다.
6. Mac 브라우저에서 `http://127.0.0.1:5174/`로 접속한다. 실제 기기 IP와 기기 토큰을 넣고 **안정 320×240 → ESP32 연결**을 누른다. 웹의 실제 센서명, 사진 수, 프레임 번호, 마지막 수신을 확인한다. 화질 변경은 버전 0.3.4가 확인된 경우에만 시도한다.
7. 폴이 클립 앞의 빨강/초록/신호 없음 입력을 바꾼다. 사진 갱신, 판독, 최종 대기, 직접 들리는 안내가 한 화면/녹음에 담기게 한다. 테스트 화면/인쇄물이라면 종류를 그대로 기록한다. C-ITS 실시간 정보가 없으면 최종 판정은 대기다.

## 오늘 채울 기록

- 폴 실행 시각/장소: 미기입
- Mac OS/브라우저: 미기입
- USB 포트: 처음에는 인식되지 않았으나 재연결 후 `/dev/cu.usbmodem1101` 확인. 폴이 직접 컴파일·업로드 완료.
- 펌웨어 버전/모드/IP/센서: `0.3.4` / `STA` / `192.168.0.26` / `cameraOk true`; 프로필 `stable`, RSSI `-75 dBm`. 센서명은 부팅 로그의 후속 줄 확인 필요.
- Python probe 결과/사진 파일: 첫 시도는 3.005초 후 0바이트로 실패. 재시도는 HTTP 200, stable 320×240, JPEG quality 12, Content-Length/실제 수신 4,898바이트 일치, 0.040초, JPEG 시작·끝 표식 True, 전송 오류 0건으로 성공. Mac 파일 `/tmp/clipsense-probe.jpg`.
- 네트워크 재확인: Mac `192.168.0.73`, ESP32 `192.168.0.26`. 무인증 `GET /health`가 HTTP 401 `missing_device_token`으로 응답해 같은 망의 기기 웹 서버 도달은 확인됨. 인증 사진 재시도 필요.
- 웹 주소/코드 버전/규칙 버전: 미확인
- 실제 클립 사진 갱신·프레임 번호: 미확인

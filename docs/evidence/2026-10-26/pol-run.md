# 10/26 폴 실행 기록·Flow 게시 초안

상태: **10/26 USB·STA·카메라·인증 JPEG·로컬 웹 연결 확인. 팀 영상의 판독·실제 음성 장면 촬영 필요**. 10/22 사진 수신 기록을 오늘의 성공으로 쓰지 않는다.

## 폴이 직접 처음부터 실행

1. Mac과 ESP32 전원/USB를 연결한다. 시리얼 모니터가 이미 포트를 쓰면 그 터미널에서 Control+C로 종료한다.
2. Mac에서 `arduino-cli board list`로 USB 포트를 확인한다. 포트가 보이는 것과 Wi-Fi/사진이 되는 것은 각각 따로 확인한다.
3. 프로젝트 루트에서 `arduino-cli monitor -p /dev/cu.usbmodem1101 -c baudrate=115200,dtr=on,rts=off`를 실행한다. 버전, networkMode, ip, cameraOk, cameraProfile을 적는다. 로그가 잘리면 모니터에 `status` 후 Enter.
4. 모니터를 Control+C로 닫고, 별도 터미널에서 `python3 scripts/probe_clip_snapshot.py http://<방금 확인한 IP> --profile stable`을 실행한다. HTTP 200, 수신 길이 일치, JPEG 표식 True를 확인한다. 토큰은 로컬 secrets.h에서 읽으며 화면에 공개하지 않는다.
5. `cd web` 후 `CLIPSENSE_HTTP_LOCAL=1 npm run dev -- --port 5174 --strictPort`를 실행한다. 5174가 이미 사용 중이면 기존 서버 터미널에서 Control+C로 종료하고 다시 실행한다. 웹은 React/Vite이며, Python은 기기 사진 진단 도구다.
6. Mac 브라우저에서 `http://127.0.0.1:5174/`로 접속한다. 실제 기기 IP와 기기 토큰을 넣고 **안정 320×240 → ESP32 연결**을 누른다. 웹의 실제 센서명, 사진 수, 프레임 번호, 마지막 수신을 확인한다. 화질 변경은 버전 0.3.4가 확인된 경우에만 시도한다.
7. 폴이 클립 앞의 빨강/초록/신호 없음 입력을 바꾼다. 사진 갱신, 판독, 최종 대기, 직접 들리는 안내가 한 화면/녹음에 담기게 한다. 테스트 화면/인쇄물이라면 종류를 그대로 기록한다. C-ITS 실시간 정보가 없으면 최종 판정은 대기다.

## 오늘 채울 기록

- 폴 실행 시각/장소: 미기입
- Mac OS/브라우저: 미기입
- USB 포트: 처음에는 인식되지 않았으나 재연결 후 `/dev/cu.usbmodem1101` 확인. 폴이 직접 컴파일·업로드 완료.
- 펌웨어 버전/모드/IP/센서: `0.3.4` / `STA` / `192.168.0.26` / `cameraOk true`; 프로필 `stable`, RSSI `-75 dBm`. 센서명은 부팅 로그의 후속 줄 확인 필요.
- Python probe 결과/사진 파일: 첫 시도는 3.005초 후 0바이트로 실패. 재시도는 HTTP 200, stable 320×240, JPEG quality 12, Content-Length/실제 수신 4,898바이트 일치, 0.040초, JPEG 시작·끝 표식 True, 전송 오류 0건으로 성공. Mac 파일 `/tmp/clipsense-probe.jpg`.
- 네트워크 재확인: Mac `192.168.0.73`, ESP32 `192.168.0.26`. 무인증 `GET /health`가 HTTP 401 `missing_device_token`으로 응답해 같은 망의 기기 웹 서버 도달을 확인했고, 이후 인증 사진 수신도 성공.
- 웹 주소/코드 버전/규칙 버전: `http://127.0.0.1:5174/` / `f1655f6` / `hsv-components-v3`. 실제 화면 녹화에서 다시 확인 필요.
- 실제 클립 사진 갱신·프레임 번호: 미확인
- 입력 장면/정답/판독/최종 안내: 미확인
- 음성 직접 청취/영상 녹음 재생: 미확인

- 바꾼 실행 메모의 정확한 줄(한 곳):
  - 수정 전: `Mac과 ESP32 전원/USB를 연결한다.`
  - 수정 후: `ESP32 본체 USB-C를 데이터 케이블로 Mac에 직접 연결하고, board list에서 /dev/cu.usbmodem 포트를 확인한다. 전원 LED만 켜지고 포트가 없으면 케이블을 다시 꽂아 인식부터 복구한다.`
  - 실제 이유: 처음에는 LED만 켜지고 USB 포트가 없었지만 재연결 후 `/dev/cu.usbmodem1101`이 나타나 업로드와 촬영에 성공했다.
- 자료 ① 실제 실행 기록·원본 사진 위치: 이 문서의 10/26 USB·STA·Python probe 기록, Mac `/tmp/clipsense-probe.jpg`. 제출 폴더로 복사할 위치는 미정.

- 재사용한 이전 장면·파일: 미기입 (10/22 영상은 오늘 촬영으로 표기하지 않음)

## 오늘 팀 영상 촬영 순서

한 영상으로 ①과 ②가 이어지도록 휴대폰으로 Mac 화면·폴의 손·실제 소리를 함께 촬영한다. 토큰 입력 장면은 프레임 밖으로 빼거나 촬영 전에 입력한다.

1. 실행 메모의 `폴이 직접 처음부터 실행` 부분과 폴이 USB 케이블을 직접 연결하는 모습을 함께 담는다.
2. `board list`의 `/dev/cu.usbmodem1101`, 시리얼 `0.3.4 / STA / 192.168.0.26 / cameraOk true` 또는 저장한 실행 로그를 보여준다.
3. 로컬 웹 `127.0.0.1:5174`에서 `새 사진 수신 중`, 실제 ESP32 센서, 성공 사진 수·프레임 번호·FPS가 증가하는 화면을 담는다.
4. 클립 앞에 빨강 테스트 화면을 놓고 웹 사진과 `빨간 색상 후보`, 최종 `대기`를 담은 뒤 음성 시작/다시 듣기를 눌러 실제 소리를 함께 녹음한다.
5. 초록 테스트 화면으로 바꿔 사진 변화, `초록 색상 후보`, 실제 남은 시간 없음에 따른 최종 `대기`, 실제 음성을 담는다.
6. 신호 없는 장면도 짧게 보여 `신호등을 확인할 수 없습니다`와 대기 음성을 담는다.
7. 녹화를 끝낸 뒤 영상을 재생해 화면 변화와 음성이 실제로 들어갔는지 폴이 직접 확인한다.

권장 파일명: `2026-10-26_pol_clip_web_vision_audio.mov`. 영상 촬영이 막히면 `/tmp/clipsense-probe.jpg`, 이 문서의 실행 로그, 웹 화면 사진, 세션 JSON의 speech 이벤트를 함께 제출하되 speech 이벤트는 실제 청취 증거가 아니라고 적는다.

## 자료 ①②③ 제출 문장

- ① 폴이 기존 실행 메모를 보고 데이터 케이블 연결, USB 포트 확인, ClipSense 펌웨어 상태 확인, 로컬 웹 연결을 직접 수행했다. 근거는 팀 영상 `[시간 구간]`과 이 문서의 실행 로그다.
- ② 실제 ESP32 클립 앞의 빨강·초록·신호 없음 입력이 웹 사진 갱신과 `hsv-components-v3` 판독으로 이어졌고, 실제 남은 시간이 없어 최종 안내는 대기로 유지됐다. 음성은 팀 영상 `[시간 구간]`에서 직접 확인한다.
- ③ 실행 메모의 USB 연결 한 줄을 위의 수정 전/후와 같이 바꿨다. 전원 LED만 확인하던 절차에 데이터 케이블과 `/dev/cu.usbmodem` 확인을 추가해 같은 연결 문제를 바로 구분하도록 했다.
